## 목표
v25 03이 남긴 두 구멍을 메운다: 실패로 끝난 수리 worker의 `브랜치 밖 원인:` 표식을 무시하는 것과, 다시 띄우지 못한 수리 worker의 앞 실행 메시지를 잃는 것.

## 완료 조건
- 수리 worker 결과에 "이번 실행에서 worker를 실제로 시작했는가"와 마지막 메시지의 출처(이번 실행 / 앞 실행)를 명시적으로 남긴다. 로그 파일이 있는지로 추정하지 않는다: `_resume`이 다시 띄우지 못해 앞 실행 디렉터리로 대신 결과를 만든 경우(새 디렉터리를 만들기 전 실패, agy 한도 포함)도 "시작 안 함 / 앞 실행"이다.
- 이번 실행에서 시작해 커밋 없이 끝난 수리 worker의 마지막 메시지에 `브랜치 밖 원인: <이유>` 줄이 있으면 종료 코드와 상관없이 `retry=False`로 실패한다. 표식이 없으면 지금과 같다.
- 이번 실행에서 시작하지 않았으면, 앞 실행 로그의 마지막 메시지를 "(앞 실행)" 표시와 함께 실패 이유 요약과 `worker-last.txt`에 싣고, 다음 시도 brief·실패 요약에 그 파일 경로를 넘긴다. 이 메시지의 `브랜치 밖 원인:` 줄은 재시도 판단에 쓰지 않는다(끊긴 실행이다). 앞 실행에도 메시지가 없으면 지금처럼 "마지막 메시지 없음"이다.
- 시험 `tests/test_verify_repair.py`: 표식+종료 1 → `retry=False`; 표식 없음+종료 1 → 지금처럼 재시도; 새 디렉터리를 만들기 전 다시 띄우기 실패 → "(앞 실행)" 메시지와 `last` 경로, 재시도 유지; 앞 메시지에 표식이 있어도 재시도 유지; 연속 두 번 재개 실패; 앞 실행 메시지도 없음 → "없음". 출처 구분이나 표식 무시 분기를 지우면 실패한다.
- `go.py`의 관련 docstring을 고친다.
